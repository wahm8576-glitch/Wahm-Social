# TikWahm على Render — نسخة تجريبية

هذه النسخة تستقبل تحديثات تيليجرام عبر **Webhook** وتعرض صفحة حالة على `/` وفحصًا تقنيًا على `/health`. يستمع الخادم إلى المنفذ الذي يمرره Render عبر `PORT`، ويضبط عنوان webhook تلقائيًا من `RENDER_EXTERNAL_URL`.

## إعداد الخدمة

1. في Render أنشئ **Web Service** للمستودع `Wahm-Social`، واختر الفرع `cue/tikwahm-render-webhook`.
2. اجعل **Root Directory** هو `tikwahm-bot`، و**Runtime** هو Docker، و**Plan** هو Free. استخدم `/health` كمسار فحص الصحة إن طُلب.
3. أضف متغير البيئة `BOT_TOKEN` بقيمة توكن بوت TikWahm التجريبي. لا تضف التوكن إلى Git أو إلى ملف الإعداد.
4. أضف `TIKWAHM_PROXY_LIST_FILE=/etc/secrets/proxy_pool.txt`.
5. من صفحة **Environment → Secret Files** ارفع ملف البروكسي باسم `proxy_pool.txt`. لا تحفظه داخل المستودع.
6. بعد اكتمال النشر، افتح `/` للتأكد من ظهور صفحة الحالة، ثم أرسل `/start` إلى البوت.

لا يحتاج الإعداد إلى `WEBHOOK_SECRET`: يُشتق سر webhook بصيغة مقبولة لدى Telegram من توكن البوت وعنوان الخدمة، ولا يُسجّل في السجلات.

## ملاحظات للتجربة المجانية

- وجود منفذ وصفحة حالة لا يمنع السكون. خدمة Render المجانية تدخل في السكون بعد 15 دقيقة بلا طلبات واردة؛ تستيقظ عند وصول تحديث تيليجرام، وقد تتأخر أول استجابة قليلًا.
- هذه نسخة تجريبية وليست ضمانًا لتوافر دائم. قد تنفد ذاكرة الخطة المجانية أثناء تشغيل Chromium، لذلك يحد الكود تشغيل متصفح واحد في الوقت نفسه.
- يُعاد تعيين الكاش الموجود بالذاكرة بعد أي إعادة تشغيل للخدمة.
- لا تضف ملف البروكسي أو أي توكن إلى Git. ملف البروكسي المرفوع هو بيانات اعتماد سرية.
